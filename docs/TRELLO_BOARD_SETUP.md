# 🏛️ บอร์ดที่ 1: Requirement Management
ให้สร้าง Lists ทั้งหมด 8 Lists ดังนี้:

### List 1: Problems (ปัญหาที่ต้องแก้ไข)
- **การ์ด 1:** นักศึกษาและบุคลากร มธ.รังสิต เดินไปโรงอาหารแล้วพบว่าร้านประจำปิด ทำให้เสียเวลาเรียนและเวลาพักกลางวัน
- **การ์ด 2:** ไม่ทราบล่วงหน้าว่าวัตถุดิบหรือเมนูอาหารหมดแล้ว ทำให้ต้องต่อคิวยาวแล้วไม่ได้ทาน
- **การ์ด 3:** ข้อมูลเวลาเปิด-ปิดร้านอาหารใน มธ.รังสิต ไม่แน่นอน บางร้านปิดก่อนเวลา หรือหยุดกะทันหัน
- **การ์ด 4:** โรงอาหารกรีนแคนทีนและคณะวิทยาศาสตร์มีนักศึกษาหนาแน่น แต่ไม่มีระบบกลางในการแสดงสถานะร้านอาหาร

### List 2: Needs (ความต้องการที่ได้จากการเก็บ Requirement)
- **การ์ด 1:** ต้องการระบบที่สามารถเปิดดูสถานะ เปิด/ปิด ของร้านอาหารได้ทันทีบนมือถือ โดยไม่ต้องดาวน์โหลดแอปหรือล็อกอิน
- **การ์ด 2:** ต้องการระบบค้นหาที่พิมพ์ชื่อร้าน หรือชื่อเมนูอาหารที่อยากทานได้
- **การ์ด 3:** ต้องการระบบแยกหมวดหมู่ตามโรงอาหาร (กรีนแคนทีน และ คณะวิทย์) และประเภทอาหาร
- **การ์ด 4:** แม่ค้าต้องการเครื่องมือสลับสถานะร้าน (เปิด/ปิด) ที่กดง่ายด้วยปุ่มเดียวผ่านมือถือ โดยใช้เบอร์โทร + PIN

### List 3: Constraints (ข้อจำกัดและข้อบังคับ)
- **การ์ด 1:** ระบบฝั่งผู้ใช้งาน (ลูกค้า/นักศึกษา) ต้องเข้าดูได้ทันทีโดยไม่ต้องลงทะเบียนหรือล็อกอิน (Zero Friction)
- **การ์ด 2:** ระบบฝั่งแม่ค้าต้องไม่ใช้ SMS OTP เพื่อลดต้นทุนค่าบริการ จึงปรับเป็นระบบ Phone + PIN 4-6 หลัก
- **การ์ด 3:** เน้นเฉพาะ 2 โรงอาหารหลักที่มีผู้ใช้บริการหนาแน่น: โรงอาหารกรีนแคนทีน และ โรงอาหารคณะวิทยาศาสตร์
- **การ์ด 4:** ต้องสามารถ Build และรันบน Docker Container ในเครื่องห้องปฏิบัติการได้อย่างราบรื่น

### List 4: Stakeholders (ผู้มีส่วนได้ส่วนเสีย)
- **การ์ด 1: นักศึกษาและบุคลากร มธ.รังสิต (Customer / User)** — ผู้บริโภคที่ต้องการทราบสถานะร้านอาหารล่วงหน้า
- **การ์ด 2: แม่ค้าและเจ้าของร้านอาหาร (Store Vendor)** — ผู้บริหารจัดการร้าน เปิด/ปิดร้าน และอัปเดตข้อมูล
- **การ์ด 3: ฝ่ายบริหารอาคารสถานที่ / งานบริหารโรงอาหาร มธ.** — กำกับดูแลความเรียบร้อยและผังร้านค้า
- **การ์ด 4: ผู้ดูแลระบบ (System Admin)** — ผู้ดูแลความปลอดภัย เพิ่มร้านค้า และสนับสนุนการทำงานของระบบ

### List 5: Features (คุณสมบัติของซอฟต์แวร์)
- **การ์ด 1: Real-time Status Indicator** — ป้ายแสดงสถานะ เปิด/ปิด พร้อมไฟกระพริบ และข้อความแจ้งเตือน
- **การ์ด 2: Smart Search & Multi-Filters** — ค้นหาชื่อร้าน ชื่อเมนู ฟิลเตอร์โรงอาหาร และหมวดหมู่อาหาร
- **การ์ด 3: Canteen & Booth Location Guide** — ข้อมูลที่ตั้งร้าน หมายเลขล็อค จุดสังเกต และรายการเมนู
- **การ์ด 4: Vendor PIN Authentication** — ล็อกอินแม่ค้าด้วยเบอร์โทรและรหัส PIN ปลอดภัย
- **การ์ด 5: Vendor Quick Toggle Switch** — ปุ่มสลับสถานะร้านเปิด/ปิด พร้อมบันทึกข้อความแจ้งเตือน

### List 6: Use cases
- **UC1: ตรวจสอบสถานะร้านอาหาร (Check Shop Status)** — User ดูสถานะร้านในโรงอาหาร
- **UC2: ค้นหาและกรองร้านอาหาร (Search & Filter Shops)** — User ค้นหาชื่อเมนู/ชื่อร้าน และกรองตามโรงอาหาร
- **UC3: ดูรายละเอียดและที่ตั้งร้าน (View Shop Details & Location)** — User ดูผังล็อคและเมนูอาหาร
- **UC4: เข้าสู่ระบบร้านค้า (Vendor Login)** — Vendor ล็อกอินด้วยเบอร์โทร + PIN
- **UC5: ปรับเปลี่ยนสถานะเปิด/ปิดร้าน (Update Shop Status)** — Vendor กดเปิดหรือปิดร้าน

### List 7: User stories (Product Backlog)
รวม User Stories ทั้ง 14 ตัว (Sprint 1: U1-U5 และ Sprint 2: U6-US14)

### List 8: Task & Issues (Product Backlog)
รวมรายการประเด็นทางเทคนิคและสถาปัตยกรรมระบบ

### 🟢 การ์ดที่ 1: U1: ตรวจสอบสถานะเปิด/ปิดร้านอาหารแบบ Real-time
- **Label:** `User Story`, `Sprint 1`, `Priority: High` (สีส้ม/เขียว)
- **Checklist (0/2):**
  - [ ] วิเคราะห์สถานะร้านและออกแบบ Real-time Polling
  - [ ] ทดสอบการแสดงผลป้ายเปิด/ปิดตามสถานะจริง
- **Description:**
```text
As a: นักศึกษาและบุคลากร มหาวิทยาลัยธรรมศาสตร์ ศูนย์รังสิต
I want to: สามารถตรวจสอบสถานะเปิดหรือปิดของร้านอาหารในโรงอาหารกรีนแคนทีน และโรงอาหารคณะวิทยาศาสตร์ ได้ทันทีผ่านหน้าเว็บมือถือ โดยมีการอัปเดตสถานะที่รวดเร็ว
So that: ไม่ต้องเสียเวลาเดินไปดูหน้าร้านด้วยตนเอง สามารถวางแผนการรับประทานอาหารได้อย่างสะดวก รวดเร็ว และมีข้อมูลประกอบการตัดสินใจทันที

ระดับความสำคัญ (Priority): High
คะแนนความยาก (Estimate): 16 Story Points (hours)

Acceptance Criteria:
1. หน้าร้านอาหารแสดงป้ายสถานะ "เปิดอยู่" (สีเขียว พร้อมจุดกระพริบ Live) หรือ "ปิดแล้ว" (สีแดง/เทา) ชัดเจน
2. มีการแสดงเวลาเปิด-ปิดทำการปกติของร้าน
3. มีปุ่มกดรีเฟรชข้อมูลสถานะสดทันที พร้อมระบบตรวจสอบสถานะใหม่อัตโนมัติ (Polling) สม่ำเสมอ
4. หากร้านมีการแจ้งเตือนเพิ่มเติม (Status Note) เช่น "ของหมด", "พักเบรก 15 นาที" ระบบต้องแสดงข้อความให้ผู้ใช้เห็นทันที

Definition of Done (Test Cases):
- TC1.1: เมื่อร้านอาหารมีสถานะ isOpen = true หน้าจอต้องแสดงป้าย "เปิดอยู่" สีเขียวสดใส
- TC1.2: เมื่อร้านอาหารมีสถานะ isOpen = false หน้าจอต้องแสดงป้าย "ปิดแล้ว" สีแดง/เทา พร้อมข้อความแจ้งเตือน
- TC1.3: เมื่อแม่ค้ากดเปลี่ยนสถานะที่หลังบ้าน เมื่อผู้ใช้กดปุ่มรีเฟรชหรือรอรอบตรวจอัตโนมัติ สถานะต้องเปลี่ยนตามทันที
```

### 🟢 การ์ดที่ 2: U2: ระบบค้นหาร้านอาหาร
- **Label:** `User Story`, `Sprint 1`, `Priority: High`
- **Checklist (0/2):**
  - [ ] พัฒนาช่องค้นหาชื่อร้านและชื่อเมนูอาหาร
  - [ ] พัฒนาระบบฟิลเตอร์ตามโรงอาหารและหมวดหมู่
- **Description:**
```text
As a: ผู้ใช้งานเว็บไซต์ (นักศึกษา / บุคลากร มธ.)
I want to: สามารถพิมพ์ค้นหาชื่อร้านอาหาร หรือชื่อเมนูอาหารที่ต้องการทาน พร้อมทั้งสามารถกดเลือกตัวกรองแยกตามโรงอาหาร (กรีนแคนทีน / คณะวิทย์) และหมวดหมู่อาหารได้
So that: สามารถค้นพบร้านอาหารและเมนูที่ต้องการได้อย่างรวดเร็ว โดยไม่ต้องเลื่อนหาร้านทั้งหมด

ระดับความสำคัญ (Priority): High
คะแนนความยาก (Estimate): 20 Story Points (hours)

Acceptance Criteria:
1. มีช่อง Input ให้พิมพ์ค้นหาแบบ Real-time โดยค้นหาได้จากชื่อร้าน, ชื่อเมนูอาหาร, หรือคำสำคัญ
2. มีแท็บสลับโรงอาหาร: [ทั้งหมด, กรีนแคนทีน, คณะวิทยาศาสตร์]
3. มีตัวเลือกฟิลเตอร์ "เฉพาะร้านที่เปิดอยู่"
4. มีแถบหมวดหมู่อาหาร (ข้าวแกง, ตามสั่ง, ก๋วยเตี๋ยว, ข้าวมันไก่, ส้มตำ, ของหวาน/เครื่องดื่ม)
5. หากไม่พบผลการค้นหา ต้องแสดงหน้าจอ Empty State พร้อมปุ่มล้างคำค้นหา

Definition of Done (Test Cases):
- TC2.1: พิมพ์ "กะเพรา" ในช่องค้นหา -> ต้องแสดงร้านที่มีเมนูกะเพรา เช่น "ครัวคุณยาย อาหารตามสั่ง"
- TC2.2: กดเลือกแท็บ "กรีนแคนทีน" -> ต้องแสดงเฉพาะร้านที่ตั้งอยู่ในโรงอาหารกรีนแคนทีนเท่านั้น
- TC2.3: กดปุ่ม "เฉพาะร้านที่เปิดอยู่" -> ร้านที่มีสถานะปิดแล้วต้องถูกซ่อนออกจากการแสดงผล
- TC2.4: พิมพ์คำที่ไม่มีในระบบ เช่น "xyz123" -> แสดงข้อความแจ้งเตือน "ไม่พบร้านอาหารที่ตรงกับเงื่อนไข" พร้อมปุ่มล้างตัวกรอง
```

### 🟢 การ์ดที่ 3: U3: แสดงร้านอาหารและที่ตั้ง
- **Label:** `User Story`, `Sprint 1`, `Priority: Normal`
- **Checklist (0/2):**
  - [ ] ออกแบบการ์ดร้านแสดงที่ตั้ง ล็อค และจุดสังเกต
  - [ ] พัฒนาหน้า Modal แสดงรายละเอียดร้านและเมนูทั้งหมด
- **Description:**
```text
As a: นักศึกษาที่มาใช้บริการโรงอาหาร มธ.รังสิต
I want to: ทราบข้อมูลที่ตั้งของร้าน หมายเลขล็อค จุดสังเกตในโรงอาหาร และรายการเมนูอาหารทั้งหมดพร้อมราคา
So that: สามารถเดินไปสั่งอาหารที่หน้าร้านได้ถูกตำแหน่ง ไม่สับสนกับร้านอื่นในโรงอาหาร

ระดับความสำคัญ (Priority): Normal
คะแนนความยาก (Estimate): 14 Story Points (hours)

Acceptance Criteria:
1. การ์ดร้านอาหารระบุชื่อโรงอาหารและหมายเลขล็อคชัดเจน (เช่น ล็อค G-01, ล็อค SC-01)
2. เมื่อคลิกที่การ์ดร้าน จะเปิดหน้าต่าง Modal แสดงรายละเอียดตำแหน่งที่ตั้งโดยละเอียด
3. แสดงจุดสังเกต (Landmark) เช่น ใกล้อาคาร บร.4, ติดประตูทางเข้าฝั่งลานกิจกรรม
4. แสดงรายการเมนูอาหารทั้งหมดของร้านพร้อมราคามาตรฐาน

Definition of Done (Test Cases):
- TC3.1: คลิกที่การ์ด "ร้านป้าณี ข้าวราดแกง" -> เปิด Modal แสดงรายละเอียดที่ตั้ง "โซนปีกซ้าย ติดประตูทางเข้าฝั่งลานกิจกรรม" และหมายเลข "ล็อค G-01"
- TC3.2: ตรวจสอบรายการเมนูใน Modal -> แสดงชื่อเมนูและราคาครบถ้วนถูกต้อง
- TC3.3: กดปุ่มปิด หรือคลิกพื้นที่ด้านนอก Modal -> Modal ปิดลงและกลับสู่หน้าหลักอย่างราบรื่น
```

### 🟢 การ์ดที่ 4: U4: Log in จัดการร้านอาหาร
- **Label:** `User Story`, `Sprint 1`, `Priority: High`
- **Checklist (0/2):**
  - [ ] ออกแบบหน้าจอ Login ด้วยเบอร์โทร + PIN
  - [ ] พัฒนาระบบตรวจสอบสิทธิ์และสร้าง Bearer Session
- **Description:**
```text
As a: แม่ค้า / เจ้าของร้านอาหารในโรงอาหาร มธ.รังสิต
I want to: สามารถเข้าสู่ระบบจัดการร้านของตนเองได้อย่างปลอดภัยและรวดเร็ว ด้วยเบอร์โทรศัพท์มือถือที่ลงทะเบียนและรหัส PIN 4-6 หลัก
So that: สามารถเข้าไปจัดการสถานะร้านของตนเองได้ โดยไม่มีผู้อื่นแอบอ้าง และไม่ต้องเสียค่าใช้จ่าย SMS OTP

ระดับความสำคัญ (Priority): High
คะแนนความยาก (Estimate): 18 Story Points (hours)

Acceptance Criteria:
1. มีปุ่ม "สำหรับแม่ค้า" ที่แถบเมนูด้านบน เพื่อเปิดหน้าต่างเข้าสู่ระบบ
2. แบบฟอร์มกรอกเบอร์โทรศัพท์ (10 หลัก) และรหัส PIN (4-6 หลัก)
3. มีปุ่มซ่อน/แสดงรหัส PIN (Show/Hide Password)
4. หากกรอกเบอร์โทรหรือ PIN ไม่ถูกต้อง ต้องแสดงข้อความแจ้งเตือนชัดเจน
5. มีปุ่ม One-Click Demo เพื่อความสะดวกในการทดสอบของคณะกรรมการ
6. เมื่อเข้าสู่ระบบสำเร็จ จะได้รับ Token และเปลี่ยนปุ่มด้านบนเป็นชื่อแม่ค้าพร้อมสถานะร้าน
```

## List 2: Sprint2 Backlog (User Story)
*(รายการที่แยกไว้ทำใน Sprint 2 ตามลำดับความสำคัญ พร้อมเหตุผลการแยกงาน)*

7. **U12: ดูเวลาเปิด/ปิดร้านอาหาร** — ตารางเวลาเปิด-ปิดประจำสัปดาห์ (วันจันทร์-วันศุกร์ และวันเสาร์-อาทิตย์)
8. **U13: ตั้งเวลาเปิด/ปิดร้าน** — ระบบตั้งเวลาอัตโนมัติ (Scheduler) ให้ร้านเปิดและปิดตามเวลาที่กำหนดไว้ล่วงหน้า
9. **US14: บันทึกร้านอาหารโปรด (Bookmark)** — ปุ่มกดหัวใจเพื่อบันทึกร้านโปรดไว้ที่แถบด้านบนผ่าน LocalStorage
