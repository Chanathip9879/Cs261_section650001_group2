## 🔍 ส่วนที่ 1: รายละเอียดการนำเสนอ Release Planning & Tasks (SDLC)

### 1. ความพร้อมของสภาพแวดล้อมการพัฒนา (Development Environment)
- **Frontend:** React 18, Vite 5, Tailwind CSS v3, Lucide Icons (ออกแบบตามหลัก UI/UX Pro Max สไตล์ Mobile-First)
- **Backend:** Node.js (Express framework) ทำหน้าที่เป็น RESTful API
- **Database:** Persistent JSON Data Store บันทึกสถานะร้านอาหารทันที ไม่ต้องติดตั้งโปรแกรม DB ภายนอก
- **Containerization:** Docker & Docker Compose (Multi-Stage Build) รันได้ด้วยคำสั่งเดียวในห้อง Lab

### 2. ลำดับความสำคัญของ User Stories ใน Sprint 1
1. **U1 (Real-time Status):** ปัญหาหลักคือลูกค้าไม่รู้ว่าร้านเปิดหรือไม่ จึงต้องเริ่มจากสถานะเปิด/ปิด
2. **U2 (Search & Filter):** เมื่อมีร้านแล้ว ลูกค้าต้องค้นหาและเลือกโรงอาหารได้รวดเร็ว
3. **U3 (Shop Location):** บอกตำแหน่งล็อคและเมนู เพื่อให้เดินไปซื้อได้ถูกต้อง
4. **U4 (Vendor Login):** ระบบยืนยันตัวตนแม่ค้าด้วยเบอร์+PIN เพื่อให้เข้าถึงสิทธิ์การจัดการ
5. **U5 (Status Toggle):** เครื่องมือสลับสถานะเปิด/ปิดของแม่ค้าที่ส่งผลต่อ U1 ทันที

## 💻 ส่วนที่ 2: ลำดับขั้นตอนการทำ Sprint Demo (ให้คะแนนเต็ม 30%)

1. **แสดงการ Checkout และ Build บน Docker:**
   - เปิด Terminal ในห้อง Lab แสดงคำสั่ง `docker compose up --build` หรือ `docker run -p 5000:5000 hiwkhaw-app`
   - แสดงให้เห็นว่า Container รันสำเร็จ ไร้ข้อผิดพลาด
2. **แสดงหน้าจอหลักฝั่งนักศึกษา (User View):**
   - เปิด Browser ไปที่ `http://localhost:5000`
   - ชี้ให้เห็นป้ายสถานะ 🟢 "เปิดอยู่" และ 🔴 "ปิดแล้ว" พร้อมจุดกระพริบ Live (U1)
   - ทดสอบพิมพ์ค้นหา "ข้าวมันไก่" หรือ "กะเพรา" ในช่อง Search -> ผลลัพธ์กรองทันที (U2)
   - กดสลับแท็บ "กรีนแคนทีน" และ "คณะวิทยาศาสตร์" -> กรองตามโรงอาหาร (U2)
   - คลิกการ์ดร้าน -> แสดง Modal รายละเอียดล็อค ที่ตั้ง และเมนูอาหารทั้งหมด (U3)
3. **แสดงการโต้ตอบแบบ Real-time (U4 & U5):**
   - เปิดเบราว์เซอร์อีกหน้าต่าง (Incognito หรืออุปกรณ์มือถือ)
   - กดปุ่ม "สำหรับแม่ค้า" -> ใช้ One-Click Demo หรือพิมพ์เบอร์ `0811111111` PIN `1111` (ร้านป้าณี) เข้าสู่ระบบสำเร็จ (U4)
   - ในหน้า Dashboard แม่ค้า: กดสลับสวิตช์เป็น **"ปิดร้าน"** พร้อมพิมพ์ข้อความ "พักเบรก 15 นาที" (U5)
   - สลับกลับมาดูที่หน้าจอของนักศึกษา -> **ร้านป้าณีเปลี่ยนเป็นสีแดง "ปิดแล้ว" และขึ้นข้อความแจ้งเตือนทันที!**

## 🔄 ส่วนที่ 3: บทสรุป Sprint Retrospective (สิ่งที่ต้องพูดนำเสนอ)

### 1. สิ่งที่ดำเนินไปด้วยดี (What went well)
- ทีมสามารถส่งมอบ Core MVP ทั้ง 5 User Stories (U1-U5) ได้ครบถ้วน 100% ตามแผน
- การปรับระบบล็อกอินแม่ค้าเป็น Phone + PIN ช่วยลดความซับซ้อนและไม่มีต้นทุนค่าบริการ SMS
- UI/UX ออกแบบตาม Mobile-First ให้ความรู้สึกเป็นมิตรและตอบสนองรวดเร็วแบบเดียวกับแอป Grab/Lineman
- สถาปัตยกรรมระบบสามารถ Build บน Docker ได้ราบรื่นและใช้ทรัพยากรน้อย

### 2. ปัญหาและอุปสรรคที่พบใน Sprint 1 (Challenges Encountered)
- การประสานงานเรื่องข้อมูลร้านอาหารจริงใน มธ.รังสิต (กรีนแคนทีน และ คณะวิทย์) มีรายละเอียดตำแหน่งล็อคและเมนูที่ต้องสำรวจพื้นที่จริง
- การทดสอบ Network Latency บนเครือข่าย Wi-Fi มหาวิทยาลัย (TU-WiFi) ทำให้ต้องเพิ่มระบบ Local Caching และปุ่ม Manual Refresh สำรองการ Polling

### 3. มติการปรับปรุงกระบวนการทำงานของทีม (Team Resolutions)
- กำหนดให้มีการทำ Daily Standup สั้นๆ 10 นาทีผ่าน Discord เพื่ออัปเดตการเลื่อนการ์ดบน Trello ให้สม่ำเสมอ
- เพิ่มกระบวนการ Pair Programming ในส่วนของการเชื่อมต่อ Frontend กับ Backend เพื่อลดข้อผิดพลาดในขั้นตอน Integration

## 🗺️ ส่วนที่ 4: การวางแผนสำหรับ Sprint 2 (Sprint 2 Planning)

### การพิจารณาปรับ Sprint Goals ใน Sprint 2:
- **คงเป้าหมายเดิมและต่อยอดส่วนขยาย (Enhancements):**
  - **U6: แจ้งเมนูหมด** — ให้แม่ค้าสามารถติ๊กปิดเฉพาะบางเมนูในรายการอาหารได้ (เช่น ข้าวมันไก่ทอดหมด เหลือแต่ไก่ต้ม)
  - **U9: ระบบรีวิวร้าน** — อนุญาตให้นักศึกษาเขียนรีวิวและให้คะแนนดาวได้โดยไม่ต้องล็อกอิน
  - **U13: ตั้งเวลาเปิด/ปิดร้านอัตโนมัติ** — ช่วยแม่ค้าที่ไม่สะดวกกดเปิด/ปิดร้านเองทุกวัน โดยตั้งเวลาตามตารางเรียน
  - **US14: บันทึกร้านโปรด (Bookmark)** — เซฟร้านประจำไว้ด้านบนสุดผ่าน LocalStorage
- **การปรับปรุงความปลอดภัย:**
  - เพิ่ม Rate Limiting ในการกดรหัส PIN (U7) เพื่อป้องกันการ Brute-force
- **ฝั่งผู้ดูแลระบบ (Admin Features):**
  - เพิ่มหน้า Dashboard สำหรับแอดมิน เพื่อเพิ่มหรือแก้ไขรายชื่อร้านค้าในโรงอาหารได้จากหน้าเว็บ
